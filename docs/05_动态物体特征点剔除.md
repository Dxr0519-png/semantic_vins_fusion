# 05 · 动态物体特征点剔除（中间基线）

## 1. 为什么需要这一步

VINS-Fusion 假设场景静态。行人等动态物体上的特征点会给后端带来**错误的运动约束**，导致轨迹漂移。在进入完整的物体级重建之前，先做**动态特征点剔除**，它是一个可独立验证的里程碑，同时作为物体级方案的对比基线。

## 2. 思路

用 YOLOv8-seg 的 mask 识别"动态类"（如 person、car、bicycle 等 COCO 类别），把**落在这些 mask 内的特征点**从 VINS 的优化中剔除，只保留静态背景点。

```
原图 ──► 特征提取/光流跟踪 ──► 得到特征点
            │
            ▼
YOLO mask ──► 判断每个特征点是否落在动态 mask 内
            │
            ├─ 是（动态）──► 剔除，不参与后端优化
            └─ 否（静态）──► 保留
```

## 3. 实现位置（已实现）

> 本仓库把光流跟踪**内嵌在 estimator 中**：`Estimator::inputImage` 直接调用 `featureTracker.trackImage` 得到特征帧，之后才进入后端优化。`/feature_tracker/feature` 话题与 `Estimator::inputFeature` 是原始 VINS-Fusion 节点拆分架构的残留，本仓库中 `inputFeature` 已废弃（`assert(0)`），因此"feature_tracker 输出处"对应 `Estimator::inputImage` 里 `trackImage` 返回之后的位置。

已实现的数据流：

```
/camera/color/image_raw ──► yolo_seg_node ──► /yolo/detections (Detection2DArray，含每实例 mask)
                                                   │
        vins_node  yolo_callback ◄────────────────┘  ① 按 dynamic_classes 过滤，实例 mask 合并为一张 0/1 图
                                                   │
                                  estimator.inputDynamicMask(t, merged_mask)  ② 存最新 mask（mBuf 保护）
                                                   │
        Estimator::inputImage ──► featureTracker.trackImage ──► featureFrame
                                                   │
                                  ③ 取时间最近的 mask（超 dynamic_mask_tolerance 跳过）
                                                   ▼
                          rejectDynamicFeatures：isDynamicPixel 判断特征点像素坐标是否落在 mask 内
                                                   │
                                 ├─ 是（动态）──► 从 featureFrame 剔除 + featureTracker.removeOutliers
                                 └─ 否（静态）──► 保留，进入后端优化
```

`isDynamicPixel` 已实现（mask 可相对原图下采样，先按比例映射再查表）：

```cpp
bool isDynamicPixel(double u, double v, const cv::Mat& mask, int img_width, int img_height) {
  if (mask.empty() || img_width <= 0 || img_height <= 0) return false;
  int mu = (int)(u * mask.cols / img_width);
  int mv = (int)(v * mask.rows / img_height);
  if (mu < 0 || mv < 0 || mu >= mask.cols || mv >= mask.rows) return false;
  return mask.at<uchar>(mv, mu) > 0;
}
```

> 🧭 **"外点"通道复用**：后端 `Estimator::outliersRejection`（[estimator.cpp](../ws_src/vins_fusion/vins/src/estimator/estimator.cpp#L1664)）把重投影误差大的特征 id 填进 `removeIndex`，再经 `FeatureManager::removeOutlier`（[feature_manager.cpp](../ws_src/vins_fusion/vins/src/estimator/feature_manager.cpp#L433)）与 `FeatureTracker::removeOutliers`（[estimator.cpp](../ws_src/vins_fusion/vins/src/estimator/estimator.cpp#L676)）分别清理地图与前端跟踪状态。动态剔除在 `rejectDynamicFeatures` 中**复用同一套 `FeatureTracker::removeOutliers`**（[estimator.cpp](../ws_src/vins_fusion/vins/src/estimator/estimator.cpp#L304)）：区别只是动态 id 由 mask 判定而不是重投影误差，且剔除发生在进入后端之前（本帧直接不进 `featureBuf`）。

> ⚠️ **mask 与特征点对齐假设**：yolo_seg_node 跑在 `/camera/color/image_raw`（彩色流），VINS 特征来自 `/camera/infra1|2/image_rect_raw`（红外流），两者 FOV/分辨率不同，`isDynamicPixel` 直接按"同一 FOV"做归一化映射属于**中间基线近似**。`dynamic_classes` 越保守（如只留 person），误删静态特征点的风险越小。
>
> 若需严格对齐，两条路径：
> - **几何重投影（推荐，保住检测质量）**：D435i 彩色与红外流有出厂外参，用 `rs2::align`（color → infra1）把彩色系 mask 重投影到红外系，再查表——YOLO 仍看彩色图，检测质量不降，mask 像素级对齐。需要 depth/外参配合，属 docs/07 物体级方案的进阶工作。
> - **把 YOLO 指到红外流（能跑但会掉质量）**：把 yolo 的 `image_topic` 改为 `/camera/infra1/image_rect_raw`（`cv_bridge` 会把 mono 自动转 3 通道），同相机天然对齐；但 YOLO 按可见光 COCO 训练，灰度/红外输入检测会下降，且 D435i 主动红外含投影散斑，需自行评估。**"用红外识别"≠"识别红外"**——模型不认识红外模态，不能指望白拿。

> 更精确的做法是用 `cv::pointPolygonTest` 判断点是否在分割的多边形内，处理 mask 边界；或结合几何一致性（§6）判断是否真的在运动。

## 4. 动态类集合

运行时由 **VINS 配置** [realsense_stereo_imu_config.yaml](../ws_src/vins_fusion/config/realsense_d435i/realsense_stereo_imu_config.yaml) 的 `dynamic_classes` 决定（另有 `dynamic_remove` 开关、`dynamic_mask_tolerance` 时间容差）；[object_slam.yaml](../ws_src/object_slam/config/object_slam.yaml#L5) 中同名配置保留为语义清单（供后续物体级方案参考）。COCO 常用动态类：

| COCO id | 类别 |
|---|---|
| 0 | person |
| 2 | car |
| 3 | motorcycle |
| 5 | bus |
| 6 | train |
| 7 | truck |
| 1 / 4 / 8 / 9 | bicycle / airplane / boat / ...（按场景取舍） |

> 注意"潜在动态"（如停在路边的车）与"确实运动"（正在走的人）的区别。简单方案是**保守剔除**：只要属于动态类就剔除；进阶方案是结合**几何一致性**（重投影误差 / 对极约束）判断是否真的运动，见 §6。

## 5. 验证

在 TUM `fr3_walking_*` 序列或实机有人走动的场景下对比。切换配置里 `dynamic_remove: 0`（纯 VINS 基线）与 `dynamic_remove: 1`（有剔除）各跑一遍，对比轨迹误差：

| 指标 | 无剔除 | 有剔除 |
|---|---|---|
| ATE/RPE（绝对/相对轨迹误差） | 基准 | 应更低 |

用 `evo_ape` / `evo_rpe` 评估（见 [`docs/10`](10_运行与验证.md)）。也可临时订阅观察：`ros2 topic echo /yolo/detections` 确认 mask 正常，VINS 日志中 `dynamic removal: N feature(s) removed` 确认剔除生效。

## 6. 进阶：几何一致性验证（可选）

仅靠类别会误伤"静止的桌子（类别 chair）旁边的静止人像"。更鲁棒的做法：

1. 特征点先按类别粗筛；
2. 对候选动态点，用**对极几何**验证：计算点到对极线距离，若明显大于阈值且方向一致，才判定为运动。

这条路径与物体级方法互补，可作为未来工作（文档里留接口即可）。

## 7. 与物体级方案的关系

| 方案 | 作用对象 | 输出 |
|---|---|---|
| 动态点剔除（本章） | 特征点 | 更干净的静态点 → 提升定位 |
| 物体级重建（docs/06~08） | 物体 | 物体地图 + 联合优化 |

物体级方案**天然包含**动态点剔除的收益（动态物体被建模为独立椭球，不再污染静态背景），因此本章是理解问题的铺垫，也是最终系统的基线对照。
