# 05 · 动态物体特征点剔除（中间基线）

## 1. 为什么需要这一步

VINS-Fusion 假设场景静态。行人等动态物体上的特征点会给后端带来**错误的运动约束**，导致轨迹漂移。在进入完整的物体级重建之前，先做**动态特征点剔除**，它是一个可独立验证的里程碑，同时作为物体级方案的对比基线。

## 2. 思路

用 YOLOv8-seg 的 mask 识别"动态类"（如 person、car、bicycle 等 COCO 类别），把**落在这些 mask 内的特征点**从 VINS 的优化中剔除，只保留静态背景点。

```
原图 ──► 特征提取/光流跟踪 ──► 得到特征点
            │
            ▼
YOLO mask ──► 判断每个特征点是否落在动态 mask 内
            │
            ├─ 是（动态）──► 剔除，不参与后端优化
            └─ 否（静态）──► 保留
```

## 3. 实现位置

在 VINS 前端的 `feature_tracker` 之后、`estimator` 之前插入一个过滤步骤：

```cpp
// 伪代码：在 imu_callback 收到图像并完成光流跟踪后
for (auto& f : feature_frame) {
  // 把特征点 f 的像素坐标投影到 YOLO mask 图上
  bool dynamic = isDynamicPixel(f.x, f.y, yolo_mask);
  if (dynamic) {
    f.outlier = true;   // 标记为外点，后续 estimator 忽略
  }
}
```

其中 `isDynamicPixel` 查 mask 图（注意 mask 与特征点的分辨率/对齐关系）：

```cpp
bool isDynamicPixel(float x, float y, const cv::Mat& mask) {
  int u = (int)(x * mask.cols / img_width);
  int v = (int)(y * mask.rows / img_height);
  if (u < 0 || v < 0 || u >= mask.cols || v >= mask.rows) return false;
  return mask.at<uchar>(v, u) > 0;
}
```

> 更精确的做法是用 `cv::pointPolygonTest` 判断点是否在分割的多边形内，处理 mask 边界。

## 4. 动态类集合

在 `config/object_slam.yaml` 的 `dynamic_classes` 配置（COCO 常用动态类）：

| COCO id | 类别 |
|---|---|
| 0 | person |
| 2 | car |
| 3 | motorcycle |
| 5 | bus |
| 6 | train |
| 7 | truck |
| 1 / 4 / 8 / 9 | bicycle / airplane / boat / ...（按场景取舍） |

> 注意"潜在动态"（如停在路边的车）与"确实运动"（正在走的人）的区别。简单方案是**保守剔除**：只要属于动态类就剔除；进阶方案是结合**几何一致性**（重投影误差 / 对极约束）判断是否真的运动，见 §6。

## 5. 验证

在 TUM `fr3_walking_*` 序列或实机有人走动的场景下对比：

| 指标 | 无剔除 | 有剔除 |
|---|---|---|
| ATE/RPE（绝对/相对轨迹误差） | 基准 | 应更低 |

用 `evo_ape` / `evo_rpe` 评估（见 [`docs/10`](10_运行与验证.md)）。

## 6. 进阶：几何一致性验证（可选）

仅靠类别会误伤"静止的桌子（类别 chair）旁边的静止人像"。更鲁棒的做法：

1. 特征点先按类别粗筛；
2. 对候选动态点，用**对极几何**验证：计算点到对极线距离，若明显大于阈值且方向一致，才判定为运动。

这条路径与物体级方法互补，可作为未来工作（文档里留接口即可）。

## 7. 与物体级方案的关系

| 方案 | 作用对象 | 输出 |
|---|---|---|
| 动态点剔除（本章） | 特征点 | 更干净的静态点 → 提升定位 |
| 物体级重建（docs/06~08） | 物体 | 物体地图 + 联合优化 |

物体级方案**天然包含**动态点剔除的收益（动态物体被建模为独立椭球，不再污染静态背景），因此本章是理解问题的铺垫，也是最终系统的基线对照。
