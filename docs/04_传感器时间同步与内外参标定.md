# 04 · 传感器时间同步与内外参标定

## 1. 目标

- **时间同步**：让 D435i 的彩色图、红外双目、IMU 在时间戳上对齐，否则 VINS 与 YOLO 的输入对不上，物体关联会错位。
- **标定**：获得准确的内参（相机）、噪声参数（IMU）、外参（相机-IMU），这些直接决定 VINS 精度。

## 2. D435i 的硬件同步特性

D435i 内部由同一时钟驱动双目红外与 IMU，**双目与 IMU 天然硬件同步**（这是选它的关键原因）。彩色图（RGB）是独立的 ASIC 模块，与红外/IMU 存在**微小时间偏移与空间偏移**，需要单独对齐。

| 数据 | 同步性 |
|---|---|
| infra1 + infra2 + IMU | 硬件同步（VINS 直接用） |
| color(RGB) | 与上述有偏移，需 message_filters 或标定对齐（YOLO 用） |

## 3. 时间同步实现

### 3.1 VINS 内部（双目+IMU）

VINS-Fusion 前端用 `message_filters` 近似时间同步对齐双目与 IMU（ROS2 移植版逻辑一致）：

```cpp
// 思路：以图像为基准，找最近时间的 IMU 测量做预积分
message_filters::Subscriber<Image> sub_img0(nh, IMAGE0_TOPIC, 100);
message_filters::Subscriber<Image> sub_img1(nh, IMAGE1_TOPIC, 100);
message_filters::Subscriber<Imu>  sub_imu(nh, IMU_TOPIC, 200);
typedef sync_policies::ApproximateTime<Image, Image, Imu> SyncPolicy;
Synchronizer<SyncPolicy> sync(SyncPolicy(100), sub_img0, sub_img1, sub_imu);
sync.registerCallback(&imu_callback);
```

> 📄 **源码出处**（说明性代码，ROS1 `message_filters` 写法）：本仓库的 ROS2 移植版**未使用** message_filters。实际同步在 [rosNodeTest.cpp](../ws_src/vins_fusion/vins/src/rosNodeTest.cpp) —— `img0_callback` L33 / `img1_callback` L41 把图像入队，独立线程 `sync_process()` L74-140 按 **0.003s** 容差成对取出双目，`imu_callback` L143 直接喂给 estimator；订阅建立见同文件 L272-280（IMU 用 best_effort QoS）。
> object_slam 侧（YOLO 彩色图 ↔ VINS 位姿）的时间同步见 [object_slam_node.cpp](../ws_src/object_slam/src/object_slam_node.cpp) 的 `nearestKeyframe()` L98-121。

> 用户此前 `time_synchronization` 项目已练过 `ApproximateTimeSynchronizer`，这里复用同一思路。

### 3.2 YOLO（彩色图）与 VINS 位姿

object_slam 需要把"某一帧彩色图的分割结果"对应到"该帧的相机位姿"。两种做法：

- **方案 A（推荐，简单，已落地 ✅）**：按时间戳近似匹配。YOLO 结果带 `header.stamp`，object_slam 在 VINS 关键帧时间序列里找最近邻（`std::lower_bound` 二分）。
  - 实现：[object_slam_node.cpp](../ws_src/object_slam/src/object_slam_node.cpp) 的 `nearestKeyframe()`（L98-121，`std::lower_bound` 二分），在 `detectionCallback`（L42-96）开头调用（L46-58）；无关键帧或 `|dt| > time_tolerance` 时丢弃该帧。
  - 配置：[object_slam.yaml](../ws_src/object_slam/config/object_slam.yaml#L7) 的 `time_tolerance: 0.05`（秒，默认 50ms）。
  - 验证：正常运行时每帧打印 `检测帧 t -> 关键帧 t (dt=..ms) pos=(..)`，`dt` 稳定在毫秒级即为同步成功。
- **方案 B（精确，可选）**：标定出 color↔infra 的时间偏移 `t_offset`，匹配时 `t_infra = t_color + t_offset`。

### 3.3 时间偏移标定（color↔infra）

用 `rs-sensor-control` 或跑一个"闪烁光源/已知运动"记录 rosbag，比较同一事件在 color 与 infra 流中的时间戳差。工程上 D435i 的偏移通常在**毫秒级**，若物体运动慢，方案 A 足够。

### 3.4 标定前置：三个终端三行命令

标定/录制全程开 **3 个终端**，命令如下（录制命令以 6.1 外参标定为例；4.2 内参、5 IMU 的话题不同，见对应小节）：

```bash
# ── 终端1：启动相机 ──
# 必须用项目封装版（已开 IMU 融合 + 双目 infra + 640x480）
# 裸 rs_launch.py 默认不开 IMU/infra，录出来没有 IMU 数据
ros2 launch vins rs_camera.launch.py

# ── 终端2：录制标定 bag ──
ros2 bag record -o imu_cam \
  /camera/color/image_raw /camera/infra1/image_rect_raw \
  /camera/infra2/image_rect_raw /camera/imu

# ── 终端3：预览画面（确认标定板始终在视野内）──
ros2 run rqt_image_view rqt_image_view /camera/infra1/image_rect_raw
```

> 话题前缀是 **`/camera/`**（单层）——[rs_camera.launch.py](../ws_src/vins_fusion/vins/launch/rs_camera.launch.py) 设 `camera_namespace: '/'` + 节点名 `camera`；若用默认 namespace（camera）话题会变成双层 `/camera/camera/...`，与 VINS/YOLO 配置不匹配。VINS 配置 [realsense_stereo_imu_config.yaml](../ws_src/vins_fusion/config/realsense_d435i/realsense_stereo_imu_config.yaml#L8-L10) 里的 `imu_topic`/`image0_topic`/`image1_topic` 均为该前缀。

录制前先确认话题在发（终端2 里跑一下，有数据再开始录）：

```bash
ros2 topic hz /camera/imu
ros2 topic hz /camera/infra1/image_rect_raw
```

## 6. 相机-IMU 外参标定（kalibr）

### 6.1 录制标定数据（动作要诀）

`imu_cam.bag` 不是普通"拍视频"，而是**图像流 + IMU 流同步录制**。标定质量几乎完全取决于动作怎么录——核心原则是**慢、平滑、充分激励 IMU 的 6 个自由度**。

录制命令（三终端分工见 3.4）：

```bash
ros2 bag record -o imu_cam \
  /camera/color/image_raw /camera/infra1/image_rect_raw \
  /camera/infra2/image_rect_raw /camera/imu
```

录制前先确认话题在发（见 3.4），录完检查四个话题的消息数是否都与时长相符：

```bash
ros2 bag info imu_cam
```

**整体节奏（分 5 段）：**

| 阶段 | 时长 | 动作 |
|---|---|---|
| ① 静止 | 5~10 s | 相机不动，正对标定板——用于估计 IMU bias 与重力方向 |
| ② 水平 8 字 | 30~40 s | 横卧 ∞ 轨迹（见下） |
| ③ 竖直 8 字 | 30~40 s | 竖立 ∞ 轨迹 |
| ④ 8 字 + 自旋 | 30~40 s | 重复水平 8 字（横卧 ∞），同时绕光轴（z 轴）缓慢自旋；也可换竖直 8 字 |
| ⑤ 静止 | 3~5 s | 收尾，帮助 bias 收敛 |

**8 字怎么走：**

- **水平 8 字（横卧 ∞）**：保持相机正对棋盘格，在空中画一个"躺着的 8 字"——先水平画一个圆，再反向画另一个圆，两圆在中间相切。整个轨迹落在一个大致水平的平面上，走完一个 ∞ 约 5~10 秒，**全程保持画面里有棋盘格**。
- **竖直 8 字（竖立 ∞）**：在竖直平面画数字 8 的轨迹，上下两个环。与水平 8 字互补，激励不同方向的 IMU 轴。
- **8 字 + 自旋**：这里用的"8 字"是**水平 8 字（横卧 ∞）**，即与阶段②相同的轨迹，区别只在叠加一个动作——走 ∞ 的同时，让相机绕自身光轴（z 轴，即指向标定板的那根轴）缓慢旋转 90°~180°，像拿着相机缓慢"拧手腕"，全程让标定板保持在画面中心附近。若想激励更充分，这轮也可换成竖直 8 字上叠加同样的自旋。目的：纯平面 8 字走下来相机一直"平端"着，绕光轴的滚转自由度几乎没被激励，叠加自旋后三轴陀螺仪才都被转动。

**关键禁忌：**

| 禁忌 | 原因 |
|---|---|
| 只做纯平移 | 陀螺仪无激励，外参旋转部分不可观 → 标定发散 |
| 只绕单一轴转动 | 其他轴没被激励，解不唯一 |
| 动作急停急转 | 加速度冲击会污染 IMU 积分 |
| 标定板跑出画面/被遮挡 | 该段视觉位姿丢失，产生空洞 |
| 板太小、光照不均/反光 | Aprilgrid 角点检测不稳定 |

> 标定板固定、手拿相机移动，比"相机固定、移动板"更稳定——抖动小，角点更清晰。

### 6.2 运行 kalibr（转格式 → x86 电脑）

kalibr 官方**只有 ROS1 版**（无 ROS2 支持，也没有 arm64 镜像），所以完整流程是：**Jetson 上录 bag → 转 ROS1 格式 → 拷到 x86 电脑跑 kalibr**。x86 电脑是 Ubuntu 24.04（只有 ROS2 Jazzy，无原生 ROS1），ROS1 环境用 Docker 容器提供。

**① Jetson：rosbag2 → ROS1 .bag**

```bash
pip install "rosbags==0.9.23"   # 锁 0.9.x：新版本(0.10+)CLI 改为 --src/--dst 且不再支持输出 ROS1 .bag
rosbags-convert imu_cam        # 与 imu_cam/ 同目录生成 imu_cam.bag
```

**② 拷到 x86 电脑**（scp/U 盘），需要 4 个文件：

| 文件 | 来源 |
|---|---|
| `imu_cam.bag` | ① 转换产物 |
| `calib_cam-camchain.yaml` | 4.2 内参标定的输出（含各相机话题名） |
| `imu.yaml` | 5 节 imu_utils 的噪声参数 + `rostopic: /camera/imu` + `update_rate: 199` |
| `april_6x6.yaml` | 标定板定义（tagSize 与你打印的板一致） |

**③ x86 电脑（Ubuntu 24）：Docker 容器里装 ROS1 Noetic + kalibr**

先确认有 Docker（`docker --version`；没有则 `sudo apt install docker.io && sudo usermod -aG docker $USER` 后重新登录）。然后起容器并把 kalibr 源码挂进去：

```bash
docker run -it -v ~/kalibr:/kalibr_src -v $(pwd):/data ros:noetic-ros-base-focal bash
```

> 容器内 ROS1 环境已就绪（`source /opt/ros/noetic/setup.bash`）。`~/kalibr` 换成你克隆 kalibr 的实际路径；`$(pwd)` 是放 bag 和 yaml 的工作目录。

容器内编译 kalibr（依赖约 5 分钟，编译 -j4 约 10 分钟）：

```bash
apt update && apt install -y python3-catkin-tools git wget autoconf automake \
  libeigen3-dev libboost-all-dev libsuitesparse-dev doxygen libopencv-dev \
  libpoco-dev libtbb-dev libblas-dev liblapack-dev libv4l-dev \
  python3-dev python3-pip python3-scipy python3-matplotlib \
  python3-tk python3-igraph python3-pyx python3-wxgtk4.0 \
  ros-noetic-vision-opencv ros-noetic-camera-calibration-parsers
  # 后两行是 kalibr 运行时依赖：python3-wxgtk4.0（绘图）、vision-opencv（cv_bridge 图像读取），
  # 漏装会在运行时 ModuleNotFoundError（wx / cv_bridge）

mkdir -p /kalibr_ws/src && cd /kalibr_ws
catkin init && catkin config --extend /opt/ros/noetic --merge-devel
cp -r /kalibr_src src/kalibr
catkin build -DCMAKE_BUILD_TYPE=Release -j4
source devel/setup.bash
```

**④ 运行标定**（4 个文件先放进 `$(pwd)`，即容器里的 `/data`）：

```bash
kalibr_calibrate_imu_camera \
  --bag /data/imu_cam.bag --cam /data/calib_cam-camchain.yaml --imu /data/imu.yaml \
  --target /data/april_6x6.yaml
# 时延(td)标定：新版 kalibr（GitHub master）默认开启，无需 --time-calibration（旧版才需要该参数）
```

输出 `T_ci`（同时估计了相机-IMU 时间偏移 `td`）。**填 VINS 时须先求逆**：kalibr 的 `T_ci` = T_cam_imu（imu0 to cam0），VINS 的 `body_T_cam0` 要 T_imu_cam——直接抄会导致运动后公里级发散（2026-09-02 实测，详见 [docs/17](17_稳定配置与运行备忘.md)）。填 `config/d435i/extrinsics.yaml` 留档用同一组求逆值。

## 8. 验证标定质量

- **内参**：kalibr 重投影误差应 < 0.5 px。
- **外参**：VINS 启动后若 `estimate_extrinsic` 收敛到一个稳定值且轨迹不漂，说明初值合理。
- **时间同步**：静态场景下 YOLO 结果与 VINS 关键帧的 bbox 投影应稳定重合，无明显滞后。

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| VINS 丢帧严重 | 时间同步窗口太小/话题时间戳异常，检查 `ros2 topic hz` 与 `ros2 topic delay` |
| 标定板检测失败 | 打印清晰、光照均匀、AprilGrid 参数与 target yaml 一致 |
| 外参标定发散 | 录 bag 时做充分的多轴旋转（激励所有 IMU 轴），避免纯平移 |
