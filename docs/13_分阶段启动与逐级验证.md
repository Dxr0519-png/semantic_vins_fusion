## 1. 阶段 1 · 相机


| 验证 | 命令 | 通过标准 |
|---|---|---|
| 启动日志 | 相机终端 | `RealSense Node Is Up!` |

## 5. 阶段 5 · PC 远程 rviz（板载 rviz2 崩溃，放 PC 看）

**背景**：板载跑 rviz2 会崩（Jetson OGRE 已知问题：`std::system_error: Invalid argument`）。
PC 是 Ubuntu 24.04 + **ROS2 Jazzy 已装**（跨发行版互通：两端默认 FastDDS + 消息定义一致）。

### 5.1 板子端（重启所有节点前执行）

```bash

# 然后重启相机/VINS/YOLO/object_slam（已跑的必须重启才生效）
```

### 5.2 PC 端

> 板子上的 rviz 配置 [vins_rviz_d435i.rviz](../ws_src/vins_fusion/config/vins_rviz_d435i.rviz) 的话题与板载实际一致
> （单层 `/camera/` 前缀，对应 rs_camera.launch.py 的 `camera_namespace: '/'`），
> **务必重新 scp 获取最新版**，否则图像显示项订阅旧话题会空白。

```bash
source /opt/ros/jazzy/setup.bash
export ROS_LOCALHOST_ONLY=0
# 拷 rviz 配置（IP 换成板子 IP，覆盖旧副本）
scp zc@<板子IP>:/home/zc/semantic_ws/semantic_vins_fusion/ws_src/vins_fusion/config/vins_rviz_d435i.rviz ~/
# 打开 rviz（★ 必须带 QT 环境变量，否则崩溃，见 §5.4）
QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_egl rviz2 -d ~/vins_rviz_d435i.rviz
```

> rviz 配置与板载话题对照（修正后全部对齐）：
> | 显示项 | 话题 |
> |---|---|
> | 左目/右目图 | `/camera/infra1\|2/image_rect_raw` |
> | 彩色图 | `/camera/color/image_raw` |
> | 相机位姿 | `/camera_pose_visual`（VINS 根级话题）|
> | 轨迹/关键帧 | `/path` `/keyframe_point` `/margin_cloud` |
> | Fixed Frame | `world`（VINS 发布 world→body）|
>
> 若某显示项仍空白：rviz 左侧显示列表点开该项，核对 Topic 下拉框与 `ros2 topic list` 一致。

### 5.4 PC rviz2 崩溃排查（Ubuntu 24.04 + NVIDIA 混合显卡，2026-08-24 实测）

**现象**：`Fatal glibc error: pthread_mutex_lock.c:450 ... assertion failed: e != ESRCH || !robust` 后中止
（渲染初始化即崩，与 ROS 无关）。

按顺序执行，哪个能打开 rviz2 就锁定哪个（②③ 成功后，后续启动都带同样的环境变量前缀）：

```bash
# ① 查看显示会话类型（wayland 还是 x11；Ubuntu 24.04 默认 wayland，最易崩）
echo $XDG_SESSION_TYPE

# ② 强制 X11 协议 + EGL 集成 ★ 2026-08-24 实测有效（x11 会话下也不崩，优先用这个）
QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_egl rviz2 -d ~/vins_rviz_d435i.rviz

# ③ 软件渲染（实测仍然崩 std::system_error，无效，跳过）
# LIBGL_ALWAYS_SOFTWARE=1 rviz2 -d ~/vins_rviz_d435i.rviz

# ④ 还崩：切换显卡模式（on-demand / intel），注销重新登录后重试
sudo prime-select on-demand

# ⑤ 终极：重装/升级 NVIDIA 驱动后重启
ubuntu-drivers autoinstall
```

> **实测结论（2026-08-24）**：本机 XDG_SESSION_TYPE=x11，② 可正常打开 rviz2；③ 软件渲染仍崩
> （`std::system_error: 无效的参数`，与渲染后端无关，OGRE 线程问题）。
>
> **免每次敲长命令**（二选一，写入 ~/.bashrc 后直接 `rviz2` 即可）：
> ```bash
> # A. 环境变量全局生效（所有 Qt 程序走 xcb，一般更稳定）
> echo 'export QT_QPA_PLATFORM=xcb' >> ~/.bashrc
> echo 'export QT_XCB_GL_INTEGRATION=xcb_egl' >> ~/.bashrc
>
> # B. 或 alias 只影响 rviz2
> echo "alias rviz2='QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_egl rviz2'" >> ~/.bashrc
> ```

## 6. 故障速查（2026-08 板载实测踩坑汇总）

| 现象 | 原因 · 解决 |
|---|---|
| `ros2 --version` 报 unrecognized arguments | 正常！ros2cli 无 --version 参数，用 `ros2 -h` |
| `Package 'realsense2_camera' not found` | 未构建（第 6 步 colcon 后才有）；源码位置错 → 移入 `ws_src/` |
| torch 报 `driver too old (found version 12060)` | 装了 cu13x 版 torch（12060=CUDA 12.6 驱动）。装 jetson-ai-lab jp6/cu126 索引 + **`==` 锁版本**，勿加 `--extra-index-url` |
| `ImportError: libcudss.so.0` | 装 `nvidia-cudss-cu12`，ln 到 `/usr/local/lib/`（真实路径 `nvidia/cu12/lib/`）+ ldconfig |
| `CUDNN_STATUS_NOT_INITIALIZED` | pip 残留 cu13 的 cudnn 被 torch 扫描加载：卸载全部 cu13 的 `nvidia-*` 包 |
| `TypeError: expected np.ndarray (got numpy.ndarray)` | numpy 双版本：清 `~/.local` 的 numpy；`rm -rf` /usr/local 被污染 numpy 后重装 `<2` |
| `ml_dtypes` 崩溃（isnan）| ml-dtypes 0.6 要 numpy≥2：降级 `ml-dtypes==0.5.0` |
| `CUBLAS_STATUS_ALLOC_FAILED` | pip 的 cublas 12.9（cuDSS 依赖）与系统 12.6 冲突：卸载 `nvidia-cublas-cu12 nvidia-cuda-nvrtc-cu12 cuda-toolkit` |
| yolo 改了 yaml 不生效 | setup.py 包 config 是**复制**安装：改后 `cp` 到 install 或重新 colcon build |
| 板载 rviz2 崩溃 | Jetson OGRE 问题，不用板载 rviz，走 §5 PC 远程 |
| `camera_namespace:=''` 传参报错 | ros2 launch 不接受空值：保持默认 namespace，改 VINS 配置的话题前缀 |

## 8. 全项目验收标准（可视化看到什么才算成功）

### 8.1 静态场景（相机对着有物体的环境，如桌子+椅子）

| 层 | rviz 里看到的 | 说明 |
|---|---|---|
| VINS | 相机图像 + 特征点；`/path` 轨迹线 | 图在、轨迹在 |
| YOLO | 图像上物体被框住 + 分割 mask 叠加 | 检测识别正确 |
| object_slam | 物体上挂着椭球/二次曲面（重建）+ 点云 | 物体级重建出现 |
| 全局 | 椭球位置与画面物体对齐不漂 | 标定/关联正确 |

### 8.2 动态场景（拿相机/板子走一圈）

| 现象 | 通过标准 |
|---|---|
| 轨迹 | 平滑延伸、无跳变、无突然漂移 |
| 物体 | 椭球跟随画面物体移动，不丢不跳 |
| 物体 id | 同一物体跨帧 id 不变（`/object_slam/objects`）|
| 回环 | 走一圈回原点，轨迹闭合误差小（不严重错位）|

> ⚠️ 只看到轨迹没看到椭球 → object_slam 重建没出来：检查 `min_observations` / 动态类过滤（docs/10 §6）。

### 8.3 量化指标（正式验收，docs/10）

| 指标 | 命令 | 通过标准 |
|---|---|---|
| VINS 帧率 | `ros2 topic hz /odometry` | ~15Hz |
| YOLO 帧率 | `ros2 topic hz /yolo/detections` | ≥15Hz（当前 9.8Hz，§7.1 优化后达标）|
| 物体重建精度 | `python3 scripts/eval/eval_object_error.py --gt 0.40 0.30 0.20`（真实半轴）| 中心误差小（米级）、尺度误差 <10%、多帧稳定 |
| 轨迹精度 | evo：`evo_ape` / `evo_rpe` | 动态场景下比纯 VINS 误差下降（物体级方案价值）|

### 8.4 对照自查（哪层没出来→看哪）

| 现象 | 对应层 |
|---|---|
| 有图无轨迹 | VINS 未初始化（晃相机）|
| 有轨迹无检测 | YOLO（话题对齐 `/yolo/detections`）|
| 有检测无椭球 | object_slam（`/object_slam/objects`）|
| 椭球飘/错位 | 标定（docs/04）或关联逻辑 |
| id 跳变 | 物体关联/跟踪（docs/06）|

**一句话总结**：图像+轨迹+检测框+椭球四层同屏、动起来物体跟随且 id 稳定、走一圈轨迹闭合 = 全目标达成；之后用 evo 和标定物脚本定量打分。
