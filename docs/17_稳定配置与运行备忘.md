# 17 · 稳定配置与运行备忘（2026-09-02 定版）

> **一句话**：VINS-Fusion 在这台 Jetson + D435i 上的**稳定运行配置**与踩坑记录。按本文件的启动顺序跑即得当前最优状态：静止漂移 ~42mm/50s，运动后不发散。
> 背景：2026-09-02 全天排查"运动后公里级发散"问题，最终定位为 **kalibr 外参方向填反**（详见 §3.1）。

## 1. 当前稳定配置（realsense_stereo_imu_config.yaml）

配置文件：`ws_src/vins_fusion/config/realsense_d435i/realsense_stereo_imu_config.yaml`

| 参数 | 当前值 | 说明 |
|---|---|---|
| `imu_topic` | `/camera/imu`（**原始**） | ⚠️ M 校正节点**默认不用**：标定后相机长时间运行（>1h）偏置温漂，过时 M 校正反而注入误差导致发散（2026-09-02 实测：校正流 11.8km vs 原始流 44.6mm）；校正流仅在"标定后立即使用"时有效 |
| `body_T_cam0/1` | kalibr T_ci **求逆**后的矩阵 | 见 §3.1，方向错误是发散总根源 |
| `estimate_extrinsic` | **0**（锁定） | 方向正确后锁定即稳；在线估计反而会跑飞 |
| `estimate_td` | **0**（锁定） | `td: -0.000503`（9/2 新标定值） |
| `acc_n / gyr_n / acc_w / gyr_w` | 0.1 / 0.01 / 0.001 / 0.0001 | **宽松值 ≈ imu_utils 实测 ×8**，见 §3.2 |
| `dynamic_remove` | 0 | 动态剔除与 mask FOV 映射是近似，开启会加速发散（YOLO 运行前需先修复 docs/05 的映射） |

实测性能（2026-09-02，单相机 + 校正节点 + 上述配置）：
- 静止 50s 漂移：**~42mm**
- 短促运动（~10s）+ 静止：有界 ~300mm
- ⚠️ **连续行走：10~30 秒必发散**（6 次演示录制验证）——外参方向修正消除了"秒级爆炸"，但持续运动的残余 IMU 误差累积仍会击穿估计器。这是"超差 IMU × VINS"的组合极限，**配置层无解；需要持续运动的应用（如绕物建模）须换 ORB-SLAM3 或类似更鲁棒的实现**

## 2. 启动流程

```bash
# 终端1：相机（先确认没有其他相机节点在跑！见 §3.4）
ros2 launch vins rs_camera.launch.py

# 终端2：IMU 校正节点（M 矩阵来自 9/2 kalibr scale-misalignment 标定）
python3 scripts/imu_corrector.py

# 终端3：VINS（当前稳定版）
ros2 run vins vins_node ws_src/vins_fusion/config/realsense_d435i/realsense_stereo_imu_config.yaml

# 全栈（演示/录制时再加）：
ros2 launch yolo_seg_ros yolo_seg.launch.py
ros2 launch object_slam object_slam.launch.py
```

验证：`ros2 topic hz /imu_corrected` ≈ 199Hz（校正节点丢弃计数应 ≈ 0）；`/odometry` ~15Hz。

## 3. 核心经验（每条都是实测踩坑换来的）

### 3.1 外参方向：kalibr 的 T_ci 必须求逆才能填 VINS ⚠️ 最重要

```
kalibr 输出 "T_cam0_imu0 (imu0 to cam0, T_ci)" = T_cam_imu（从 IMU 到相机）
VINS 要求 body_T_cam0 = imu^R_cam / imu^T_cam      = T_imu_cam（从相机到 IMU）
两者互逆 → body_T_cam0 = inv(kalibr T_ci)，不是直接抄！
```

- **症状**：直接抄（不求逆）+ 锁定外参 → 一动就公里级爆炸；求逆 + 锁定 → 不发散
- 旋转接近单位阵时方向错误几乎不可见（单位阵的逆还是自己），只有平移被悄悄取反
- 文档 15 §6.1 与文档 04 §6.2④ 已同步修正为"求逆后填入"（2026-09-02）

### 3.2 噪声参数：用宽松值（≈ imu_utils 实测 ×8），不要用实测值

- imu_utils 实测（2h10min 静止）：acc_n 0.0124 / gyr_n 0.0019 / acc_w 4.3e-4 / gyr_w 1.5e-5
- **实测值填入 → VINS 过度信任这颗 IMU → 发散（验证两次）**
- 宽松值 0.1 / 0.01 / 0.001 / 0.0001（≈ ×8）→ 稳定
- 这也解释了 VINS-Fusion 官网示例为什么用这么大的噪声值（社区"×10"实践）

### 3.3 IMU 校正节点（scripts/imu_corrector.py）

- 作用：对 `/camera/imu` 应用 kalibr scale-misalignment 的 **inv(M)**（scale + 1.8° 轴对齐补偿）并滤尖峰，发布 `/imu_corrected`
- M/A 矩阵来自 9/2 重标定（**不是** 9/1 的旧值——换标定后必须同步更新脚本里的矩阵）
- ⚠️ **使用限制（2026-09-02 实测）**：校正仅在标定后相机刚开机不久时有效；连续运行数小时后 IMU 偏置温漂，过时 M 校正会把误差注入数据（校正流 11.8km vs 原始流 44.6mm）。**默认配置不用校正节点**；要用须先重标定（新 imu_cam bag + kalibr scale-misalignment）再立即运行

### 3.4 双相机节点坑（今天现场踩的）

**两个 realsense 节点同时跑 → 同一话题名双发布者 → 校正节点把交错数据全判为尖峰丢光（几万样本/秒）→ VINS 饿死（"wait for imu"）**。启动前先查：

```bash
ps aux | grep "[r]ealsense2_camera_node"   # 只能有 1 个
```
