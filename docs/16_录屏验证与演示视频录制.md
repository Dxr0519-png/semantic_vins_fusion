## 2. PC 端 · 打开 rviz

> ★ rviz 配置**必须重新 scp 最新版**：2026-09-01 新增了椭球（`ObjectEllipsoids`）与检测框
> （`YOLO_Vis`）两个显示项，旧副本看不到椭球。

```bash

scp zc@<板子IP>:/home/zc/semantic_ws/semantic_vins_fusion/ws_src/vins_fusion/config/vins_rviz_d435i.rviz ~/

QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_egl rviz2 -d ~/vins_rviz_d435i.rviz
```

打开后确认显示列表（9 项，Fixed Frame=world）：

| 显示项 | 内容 |
|---|---|
| Image ×3 | 左/右目红外 + 彩色图 |
| ObjectEllipsoids | **半透明椭球**（`/object_slam/objects_markers`，2026-09-01 新增） |
| YOLO_Vis | 检测框 + mask 叠加图（`/yolo/vis`，2026-09-01 新增） |

若某项空白：左侧显示列表点开该项核对 Topic；椭球空白多半是相机静止无关键帧（§4 走动即出现）。

## 3. PC 端 · ffmpeg 录屏

```bash
# ① 查屏幕分辨率（x11grab 需要精确尺寸）
xrandr | grep '*'        # 例如 1920x1080

# ② 开始录屏（先摆好 rviz 视角：把物体 + 轨迹都放进视野，再开录）
ffmpeg -f x11grab -framerate 30 -video_size 1920x1080 -i :0 \
  -c:v libx264 -preset ultrafast -crf 18 -pix_fmt yuv420p \
  -t 60 ~/demo_60s.mp4
```

- `-t 60`：录 60 秒自动停；想提前结束按 `q`
- 参数含义：`-f x11grab` 抓 X11 屏幕、`-i :0` 显示器 0、`-crf 18` 高画质、`-pix_fmt yuv420p` 兼容播放器
- 只录 rviz 窗口而非全屏：`xwininfo | grep "Window id"` 拿到窗口 id 后
  `ffmpeg -f x11grab -video_size 1280x800 -i :0+100,50 ...`（`+X,Y` 为窗口左上角偏移）

## 4. 录制脚本（60 秒证明流程）

| 时间 | 动作 | 视频里应看到（通过标准） |
|---|---|---|
| 0–15s | 静态展示 | 图像清晰、轨迹在、物体挂着椭球、检测框 + mask 稳定不跳 |
| 15–40s | **缓慢绕物体走半圈** | 轨迹平滑延伸、**椭球跟随画面物体移动不丢不跳**、同一物体 id 跨帧不变 |
| 40–55s | 走回原点附近 | 轨迹闭合、椭球位置与画面物体对齐不严重错位 |
| 55–60s | 停下 | 画面稳定、无抖动、无崩溃 |

> ⚠️ 关键：**必须走动**。相机静止 → VINS 无关键帧 → 椭球/地图不更新（这是设计行为，不是故障）。
> 走动速度宁慢勿快（快走会导致椭球跳变、观测丢失）。
> 若想演示"物体被遮挡再出现后 id 仍稳定"：40–55s 让一个物体短暂出画再回来。

## 5. 停止与产出

```bash
# 录屏（PC）：按 q 或等 -t 到点自动停
# 板子停止（相机最先杀，释放 USB 接口，否则下次启动报 RS2_USB_STATUS_BUSY）：
pkill -f "rs_camera.launch.py"; pkill -f "vins_node"; pkill -f "yolo_seg.launch.py"; pkill -f "object_slam.launch.py"
ps aux | grep -E "vins|yolo|object_slam|realsense" | grep -v grep || echo "已全部停止"
```

产出物：

| 文件 | 位置 | 用途 |
|---|---|---|
| `~/demo_60s.mp4` | PC | 演示视频（评审核对用） |
| `~/.ros/log/...` | PC/板子 | 运行日志（排查用） |
| `/tmp/vins_output/vio.csv` | 板子 | VINS 轨迹数据（可用 evo 出 ATE/RPE 定量分，docs/10 §8.3） |

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| ffmpeg 报 `Invalid data found when processing input` | 显示器号不对：`-i :0` 试 `:1`；或查 `echo $DISPLAY` |
| 录出来是绿屏/黑屏 | 会话是 wayland（`echo $XDG_SESSION_TYPE`）：x11grab 不支持，改用 OBS 或
  `gnome-screenshot`；或注销切回 X11（docs/13 §5.4 实测本机为 x11） |
| 录到一半 rviz2 崩 | 带 `QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_egl` 重启（docs/13 §5.4） |
| 椭球是空的/没出现 | 相机静止无关键帧 → 走动；或 rviz 配置不是最新版 → 重新 scp（§2） |
| 椭球和画面物体错位 | 标定不准（docs/04 重标定）或观测视角不足（多角度走动） |
| 磁盘不够 | bag（§7）一小时可到几 GB：只 `--topics` 录需要的，或录到外接盘 |

## 7. 备选 · ros2 bag 同录（数据留档，可回放重录）

录屏画面有瑕疵时，用 bag 数据回放重录，不必重跑实验：

```bash
# 板子上（与录屏同时跑；只录核心话题省磁盘）
ros2 bag record -o ~/demo_bag \
  /camera/color/image_raw /camera/infra1/image_rect_raw /camera/infra2/image_rect_raw \
  /camera/imu /odometry /keyframe_pose /yolo/detections /yolo/vis /object_slam/objects

# 之后任意时刻回放（板子起相机+VINS 之外的节点即可，或纯 PC 回放）
ros2 bag play ~/demo_bag
# PC 上 rviz 会随回放数据动 → 此时再录屏，保证一遍成功
```
