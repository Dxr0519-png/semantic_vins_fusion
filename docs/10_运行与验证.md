# 10 · 运行与验证

## 1. 端到端启动流程

```bash
# 0. 构建并进入容器
./scripts/build_docker.sh
./scripts/run_container.sh

# 1. 构建工作空间（首次 + 改动后）
cd /workspace
colcon build --symlink-install
source install/setup.bash
# 只调 VINS 时用：colcon build --symlink-install --packages-up-to vins

# 2. 启动传感器（D435i）
ros2 launch realsense2_camera rs_launch.py

# 3. 启动 VINS-Fusion（双目+IMU 里程计）
mkdir -p /tmp/vins_output            # VINS 输出目录（不会自动创建，见 config 内 output_path）
ros2 run vins vins_node ws_src/vins_fusion/config/realsense_d435i/realsense_stereo_imu_config.yaml
# 注：配置已按 D435i 实际标定调好（话题 /camera/infra1|2/image_rect_raw + /camera/imu，
#     IMU 订阅 QoS 已改 best_effort 并在源码打补丁，改动后需重跑 step 1 的 colcon build）
#     须从 workspace 根目录运行，calib（left/right.yaml）按配置所在目录解析

# 4. 启动 YOLO 分割
ros2 launch yolo_seg_ros yolo_seg.launch.py

# 5. 启动物体级 SLAM
ros2 launch object_slam object_slam.launch.py

# 6. 可视化（加载 VINS 轨迹/图像配置，显示 /path + 双目红外 + 彩色）
rviz2 -d /workspace/ws_src/vins_fusion/config/vins_rviz_d435i.rviz
```

## 关闭节点

> 进程 comm 被内核截断为 15 字符，realsense 节点要用截断名，`pkill -x realsense2_camera_node` 匹配不上。

```bash
pkill -x vins_node
pkill -x realsense2_came     # 不是 realsense2_camera_node
pkill -x rviz2               # 或直接关 rviz 窗口
# 确认已停（ros2 node list 有 daemon 缓存延迟，用 ps 更可靠）
ps -eo comm | grep -E "vins|realsense|rviz" || echo "全部已停"
```

## 2. 分阶段验证清单

| 阶段 | 验证命令 | 通过标准 |
|---|---|---|
| 环境 | `nvidia-smi`、`rs-enumerate-devices` | GPU 可见、相机枚举到 |
| VINS | `ros2 topic hz /odometry` | 有输出、轨迹平滑 |
| YOLO | `ros2 topic hz /yolo/detections` | ≥15Hz、mask 正确 |
| 关联 | `ros2 topic echo /object_slam/objects` | 物体 id 跨帧稳定 |
| 重建 | rviz 看椭球 | 椭球与真实物体几何吻合 |
| 联合优化 | 对比 ATE/RPE | 误差下降 |

## 3. 话题观测

```bash
ros2 topic list                                   # 总览
ros2 topic echo /yolo/detections --no-arr         # 检测（不看数组内容）
ros2 topic echo /object_slam/objects --no-arr     # 物体地图
ros2 topic hz /odometry                           # VINS 帧率（实测 ~15Hz）
ros2 topic delay /yolo/detections                 # 端到端延迟
```

## 4. 轨迹精度评测（evo）

```bash
pip install evo

# 录制 ground truth（若用 EuRoC/TUM）+ 本系统轨迹
# VINS 输出为 /odometry，可转成 tum 格式后对比
evo_ape tum groundtruth.txt trajectory.txt -va --plot
evo_rpe tum groundtruth.txt trajectory.txt -va --plot
```

> 指标含义：ATE（绝对轨迹误差，衡量全局一致性）、RPE（相对位姿误差，衡量局部漂移）。动态场景下应看到剔除/物体级方案相对纯 VINS 的误差下降。

## 5. 物体重建精度评测（scripts/eval/）

用**已知尺寸的标定物**（箱子/标定板）做定量验证：

```bash
python3 scripts/eval/eval_object_error.py --gt 0.40 0.30 0.20   # 真实半轴(米)
# 脚本订阅 /object_slam/objects，比较重建椭球半轴与真实值，输出相对误差
```

评估指标：
- **中心误差**：重建中心 vs 真实中心（米）；
- **尺度误差**：三轴半径相对误差（%）；
- **稳定性**：多帧尺度方差。

## 6. 常见端到端问题

| 现象 | 排查 |
|---|---|
| 节点起不来 | 先 `source install/setup.bash`；`ros2 pkg list` 确认包已构建 |
| YOLO 无输出 | 确认 `image_topic` 与 RealSense 实际话题一致（`ros2 topic list | grep color`） |
| 物体不出现 | `min_observations` 太高，或物体被当成动态类；降低阈值 / 检查 `dynamic_classes` |
| 椭球尺度不准 | 观测视角不足，或标定不准（重跑 docs/04 标定） |
| 内存/CPU 高 | 点云话题频率高，object_slam 做下采样或按关键帧处理 |

## 7. 录制与回放（离线调试）

```bash
# 录制所有相关话题
ros2 bag record -o debug \
  /camera/color/image_raw /camera/infra1/image_rect_raw /camera/infra2/image_rect_raw \
  /camera/imu /odometry /point_cloud

# 回放
ros2 bag play debug
```

> 离线回放能复现问题、调参，是 SLAM 调试的关键手段。建议每个问题都先录 bag 再分析。
